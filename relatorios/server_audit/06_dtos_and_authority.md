# 06 — DTOs & State Authority Matrix

Because the full backend implementation (`server/*.pyc`) is shipped inside `BSP_PAYLOAD` and runs both locally (`127.0.0.1:21749`) and on the remote server (`2.31.101.228:21760`), every DTO and state authority rule is **100% statically proven** from bytecode disassembly.

## 1. Authority Classification Summary

- **`CLIENT_AUTHORITATIVE`**: Server blindly accepts client-supplied values, overrides, or state blobs without server-side calculation or entitlement checks.
- **`MIXED`**: Server validates some constraints (e.g., item price or node existence) against server storage, but either trusts a client-supplied prerequisite (e.g., `persistentData` or `matchXpOverride`) or exposes an unguarded sibling endpoint.
- **`SERVER_AUTHORITATIVE`**: Server computes outcomes from its own database state and rejects unauthorized client overrides.
